# Matching agent — Rushitha

The [local road-routing runbook](../../../../../docs/features/live-matching.md) covers an OSRM
service, local-only seeded actors, an end-to-end worker smoke and a shared-route comparison.

`LiveMatching` is the opt-in backend gateway used by Tej's existing matching queue. Set `FOODBRIDGE_ROUTING_BASE_URL` to an OSRM-compatible driving-route endpoint, then keep `FOODBRIDGE_ENABLE_LOCAL_WORKFLOW_DEMO=false`. Without a routing URL the gateway reports `matching_service_unavailable`. The local demo still uses `DemoMatching` and must not be presented as live routing.

Candidate search uses PostGIS geography (`ST_DWithin` in metres, `ST_Distance` order) against active, verified recipients. It reads current storage-specific free capacity from `recipient_capacity`, skips excluded recipients and busy/excluded drivers, and requires a fresh authenticated self-reported driver origin. The driver client calls `GET /api/v1/driver-origin` for the version, then `POST /api/v1/driver-origin` with `Idempotency-Key`, `expected_version` and `origin`. A recipient cannot update a driver. The server timestamps the location; after five minutes it is stale. Coordinates are self-reported, not independently GPS verified. Drivers must already have a provisioned `Driver` row with availability, capacity, storage and working window. Coordinators must provision genuine driver identities/profiles before enabling the live worker.

Routing calls OSRM `route/v1/driving/{lon,lat};{lon,lat}` with a two-second per-call timeout. Searches are capped at 15 recipient routes and 5 driver routes per step, below the coordinator's 75-second lease even with a bounded shared AI request. `NoRoute` excludes that pair; timeouts, HTTP errors and malformed provider output raise retryable `routing_service_unavailable`. No Euclidean estimate is substituted for a road route. All network calls run after the candidate DB read session closes.

Mokshith's `evaluate` owns hard eligibility (food safety, capacity, dietary, storage, windows and safe-use deadline). Distance-only ranks approved candidates by road metres with a UUID tie-break. Multi-criteria uses normalized road distance, storage-specific headroom, recent active/completed reservation kilograms and candidate-specific arrival slack. Weights and bounds are versioned in `config/matching.json`. When the shared AI provider is configured, its structured output can choose only one of the top three already eligible IDs; invalid or unavailable model output falls back to deterministic ranking and records the attempted provider/model/prompt and fallback. Neither matcher writes offers or reserves capacity. The coordinator fences and rechecks versions, routes and eligibility before committing.

Run `make check` and `make integration` with real PostGIS/Redis services. See [evaluation protocol](../../../../../docs/testing.md) and [offline comparison](../../../../../evaluation/README.md). Shared identity provisioning, deployment/monitoring of a routing provider, recipient location review, affected-owner contract review and a live end-to-end deployment test remain release gates.
