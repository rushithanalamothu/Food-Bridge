# Driver workspace — Mithil

Implemented: assignments, pickup and receiving destinations, map link, storage/allergen/handling details, accept/decline, observed-weight/handling-confirmed pickup, delivery confirmation, durable donation history, newest-first pagination and scoped live snapshots. Real road routing remains a provider dependency; the frontend does not fabricate directions or ETA. See `apps/web/README.md`.

The starting-point card consumes the merged `GET/POST /driver-origin` contract. Drivers explicitly enter a description, routing coordinates and an IANA timezone; it does not geocode or request device location. Saved timestamps come from the server. Locations older than five minutes are flagged for update. Saves use the observed driver version and an idempotency key, and conflicts require an explicit reload before another save. Unavailable/unprovisioned origin reads show a retry without blocking existing assignments. Availability/profile provisioning, real routing and rematching remain backend/deployment responsibilities.
